# Zadig Agent 使用手册

本文档面向 **zadig-agent Web 平台** 的使用者，说明如何通过表单提交 Helm 项目相关申请、参与审批，并在审批通过后触发 Agent 自动在 Zadig 侧完成创建。

> 开发与部署说明见仓库根目录 [README.md](../README.md)；Kubernetes 部署见 [deploy/README.md](../deploy/README.md)。

## 一、简述

### 1.1 目标

**Zadig Agent** 是一套面向 Zadig 的 Helm 项目自助申请与自动化执行平台，主要能力包括：

| 能力 | 说明 |
|------|------|
| 表单申请 | 通过 Web 表单填写项目、服务、环境、工作流等配置，无需直接操作 Zadig 控制台 |
| 多级审批 | 按业务类型配置审批链，支持一人通过或全员通过 |
| Agent 自动执行 | 审批通过后，由 AI Agent 调用 Skill 与 Zadig MCP 工具，在 Zadig 侧创建资源 |
| 过程可观测 | 审批流详情中可查看申请内容、审批进度、Agent 执行日志与 Zadig 项目链接 |

平台当前支持的 **项目管理** 场景：

1. **创建项目** — 新建 Helm Chart 项目，并配置首个服务、测试环境、构建与工作流  
2. **添加新服务** — 向已有项目添加 Helm 服务（可复用已有环境或同时创建新环境）  
3. **添加工作流** — 为已有服务添加构建部署工作流  
4. **添加新环境** — 为已有项目添加测试或生产环境  

典型流程：

```
填写表单 → 提交申请 → 多级审批 → 申请人点击「开始执行」→ Agent 调用 Zadig API → 完成
```

![Agent 执行界面](screenshots/agent-execution.png)

### 1.2 平台地址

| 环境 | 地址 | 说明 |
|------|------|------|
| 生产环境 | 以管理员提供的域名为准，例如 `https://zadig-agent.openxlab.org.cn` | 通过 Ingress / 网关访问，支持飞书登录 |
| 本地开发 | 前端 `http://127.0.0.1:5173`，后端 API `http://127.0.0.1:8088` | 需自行启动 `webapi` 与 `npm run dev` |

**登录方式**（由管理员在 ConfigMap 中配置）：

- **飞书登录**：点击「飞书登录」跳转授权（推荐生产环境使用）
- **本地账号登录**：用户名 + 密码（开发或内网环境）

登录成功后，左侧导航栏可见 **项目管理**、**审批流** 等菜单。

页面顶部会显示 **当前 Zadig** 连接信息（名称、地址、连接状态）。若显示「不可用」，请联系管理员检查 **Zadig 管理** 中的 `base_url` 与 `api_token` 配置。

## 二、项目管理

入口：**左侧导航 → 项目管理**。各表单均支持可搜索下拉框；**代码库**、**分支** 输入关键词后会调用 Zadig 服务端检索，适合代码库数量较多的场景。

提交成功后会出现提示（含申请单号），申请进入 **审批流**。表单不会在提交后自动清空「创建项目」页面内容，其他页面会在成功后重置。

---

### 2.1 创建项目

**路径**：项目管理 → **创建项目**

**适用场景**：从零创建 Helm Chart 项目，并完成首个服务的测试环境部署能力（项目 + 环境 + 服务 + 构建 + 工作流）。

#### 基本信息

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 项目名称 | ✓ | 项目显示名称，如「我的项目」 |
| 项目标识 | ✓ | Zadig 项目唯一标识（英文、数字、连字符），会根据项目名称自动生成，可手动修改 |
| 服务名称 | ✓ | 首个 Helm 服务名称，默认同项目标识 |
| 服务模板 | ✓ | 从 **系统集成 → 服务模板** 同步的 Chart 模板中选择 |
| 环境 | — | 创建项目固定为 **测试环境** |
| 环境名称 | ✓ | 默认 `dev`，可修改 |
| 工作流名称 | ✓ | 默认「服务名称-环境名称」，如 `my-service-dev` |

> 项目标识、服务名称在手动修改后不再随项目名称自动更新。

#### K8s 集群

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 集群 | ✓ | 从 Zadig 同步的 K8s 集群中选择 |
| 命名空间 | ✓ | 可下拉选择已有命名空间，也可 **直接输入** 新建命名空间；建议格式：`项目标识-环境名称` |

#### 代码信息

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 代码源 | ✓ | GitLab / GitHub 等，从 Zadig 代码源同步 |
| 组织/用户 | ✓ | 代码仓库所属组织或用户 |
| 代码库 | ✓ | 支持搜索；输入仓库名（如 `register-fe`）后等待约 0.3 秒加载结果 |
| 分支 | ✓ | 支持搜索 |
| Values 文件 | — | 可选。点击「选择文件」从仓库目录树选取；不选则使用 Chart 模板默认值 |
| 自动同步 | — | 勾选后，Values 以代码库为准持续同步 |
| 构建上下文 | ✓ | 选择代码库后自动填充为仓库名，一般为 Dockerfile 所在目录 |
| Dockerfile 绝对路径 | ✓ | 构建上下文 + 文件名，默认 `Dockerfile` |

#### 变量配置（可选）

可添加多条构建/环境变量：

| 配置项 | 说明 |
|--------|------|
| 变量名 | 变量 key |
| 类型 | 字符串 / 单选 / 多选 |
| 作用域 | **环境变量** 或 **构建变量**（构建变量会自动生成 Docker `--build-arg`） |
| 默认值 / 可选值 | 单选、多选需通过「变量配置」弹窗维护可选值 |

#### 授权用户（可选）

- 若当前登录用户存在于 Zadig 用户列表中，会自动添加为 **project-admin** 且不可删除  
- 可继续添加其他 Zadig 用户及项目角色  

#### 提交后 Agent 将执行

审批通过并由申请人触发执行后，Agent 使用 Skill **`create_helm_project`**，依次创建 Helm 项目、绑定服务与环境、创建构建、创建工作流及授权用户。

### 2.2 添加新服务

**路径**：项目管理 → **添加新服务**

**适用场景**：向 **已有** Helm 项目增加一个新服务（及对应构建、工作流）。

#### 基本信息

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 项目名称 | ✓ | 搜索并选择已有 Zadig 项目 |
| 服务名称 | ✓ | 新服务名；若项目中已存在同名服务会提示无法提交 |
| 服务模板 | ✓ | Chart 服务模板 |
| 环境来源 | ✓ | **使用已有环境** 或 **创建新环境** |
| 环境 / 环境类型 + 环境名称 | ✓ | 选已有环境时从项目环境列表选择；选创建新环境时需指定测试/生产及环境名 |
| 工作流名称 | ✓ | 默认「服务名称-环境名称」，如 `register-be-prod` |

**环境来源说明**：

- **使用已有环境**：选择后系统尝试自动填充集群与命名空间  
- **创建新环境**：需手动选择集群与命名空间；Agent 会在添加服务时一并创建环境  

#### K8s 集群、代码信息、变量配置

字段含义与 [2.1 创建项目](#21-创建项目) 相同。

#### 生产环境说明

向 **生产环境** 添加服务时，Agent 会 **复用已有构建配置**（若存在），不会重复创建 build，仅添加服务与工作流。测试环境则会创建完整 build + workflow。

#### 提交后 Agent 将执行

Skill：**`add_helm_service`**

---

### 2.3 添加工作流

**路径**：项目管理 → **添加工作流**

**适用场景**：项目与服务、构建已存在，仅需新增一条 **构建部署工作流**（例如为生产环境补工作流）。

#### 基本信息

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 项目名称 | ✓ | 选择已有项目 |
| 环境 | ✓ | 工作流所属环境（项目下已有环境列表） |
| 工作流名称 | ✓ | 自定义名称；若已存在会实时校验并阻止提交 |
| 镜像仓库 | ✓ | 从 Zadig 同步的镜像仓库中选择 |
| 服务组件 | ✓ | 项目下已有 build 服务列表，选择后自动填充 build 名称、镜像名等 |
| 部署环境类型 | ✓ | 测试环境 / 生产环境 |
| 部署环境 | ✓ | 实际部署目标环境名称 |

#### 提交后 Agent 将执行

Skill：**`add_helm_workflow`**，按模板 `workflow_build_deploy` 创建工作流。

---

### 2.4 添加新环境

**路径**：项目管理 → **添加新环境**

**适用场景**：为已有 Helm 项目单独增加测试或生产环境（不附带新服务）。

#### 基本信息

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 项目名称 | ✓ | 选择已有项目 |
| 环境类型 | ✓ | 测试环境 / 生产环境 |
| 环境名称 | ✓ | 如 `dev`、`prod`；同项目同类型下不可重复，表单会实时校验 |

#### K8s 与镜像

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 集群 | ✓ | K8s 集群 |
| 命名空间 | ✓ | 建议 `项目标识-环境名称` |
| 镜像仓库 | ✓ | 生产环境部署使用的镜像仓库 |

#### 提交后 Agent 将执行

Skill：**`add_helm_environment`**

## 三、审批

### 3.1 审批流入口

**路径**：项目管理 → **审批流**

左侧列表按 Tab 分类：

| Tab | 适用角色 | 说明 |
|-----|----------|------|
| 任务/待办 | 审批人 | 待我审批的申请 |
| 已办 | 审批人 | 我已处理过的申请 |
| 抄送我 | 被抄送用户 | 仅通知、无需操作 |
| 已发起 | 申请人 | 我提交的所有申请 |

点击列表项可在右侧查看详情，包括：**审批进度**、**表单内容**、**Agent 执行** 等 Tab。

审批模板由管理员在 **系统设置 → 审批相关 → 审批配置** 中维护，按业务类型分别配置：

| 业务类型 | 对应申请 |
|----------|----------|
| Helm 项目申请 | 创建项目 |
| Helm 添加服务申请 | 添加新服务 |
| Helm 添加工作流申请 | 添加工作流 |
| Helm 添加环境申请 | 添加新环境 |

每类可配置多级审批、审批模式（**一人通过即可** / **需要所有人通过**）、审批人与抄送人。

### 3.2 申请人与审批人操作

#### 审批人

1. 打开 **审批流 → 任务/待办**  
2. 选中待办项，查看表单内容与审批进度  
3. 可选填写审批意见  
4. 点击 **审批通过** 或 **驳回**  

驳回后流程结束，申请人需修改后重新提交。

#### 申请人

1. 在 **已发起** 中跟踪进度  
2. 审批未完成前，可点击 **撤销申请** 终止流程  
3. 全部审批节点通过后，实例状态变为 **已完成**，流程进入 **Agent 执行** 阶段  

### 3.3 Agent 执行

审批全部通过后，**不会自动执行**，需由 **申请人** 在审批流详情中手动触发：

1. 打开 **已发起**，进入对应申请  
2. 切换到详情中的 **Agent 执行** 区域  
3. 点击 **开始执行**  
4. 在日志区域查看 Agent 逐步调用 MCP 工具的输出  
5. 执行成功后，可点击 **打开 Zadig 项目** 跳转 Zadig 控制台验证  

**其他操作**：

| 操作 | 场景 |
|------|------|
| 重新执行 | 上次执行失败且状态为「失败」 |
| 恢复连接 | 执行中页面刷新或连接断开，且服务端存在可恢复 checkpoint |
| 终止执行 | 执行过程中需要中止 |
| 回复输入框 | Agent 等待用户确认时（如 `[需要用户确认]`），输入补充说明后继续 |

执行完成后，**处理结果** 区域会显示中文摘要（项目链接、创建的资源名称等）。

> Agent 使用的模型、Skill、工作流模板、MCP 工具会在执行面板中展示，无需申请人手动选择。

### 3.4 飞书审批（可选）

若管理员已配置飞书应用，审批人可在 **飞书卡片** 中直接通过/驳回，无需打开 Web 页。申请人仍会收到状态通知。

配置要求见 [deploy/README.md](../deploy/README.md) 中飞书相关章节。

## 附录

### A. 使用前准备

普通用户只需登录平台并确认 **当前 Zadig** 可用即可。以下由 **管理员** 预先完成：

1. **Zadig 管理**：配置 Zadig 地址与 API Token，并设为生效实例  
2. **系统集成**：同步代码源、集群、镜像仓库、服务模板、Zadig 用户  
3. **Agent 管理**：配置至少一个可用的 LLM Agent（API Key、模型、Base URL）  
4. **审批配置**：为四类 Helm 申请配置默认审批模板  
5. **用户管理**（可选）：创建平台本地账号或绑定飞书  

下拉选项（代码源、集群、模板等）均来自上述同步数据；若列表为空，请联系管理员检查 Zadig 连接与同步任务。

### B. 常见问题

**Q：代码库搜索不到仓库（如 `register-fe`）？**  
A：请先选择正确的代码源与组织/用户，在代码库输入框中 **输入完整或部分仓库名** 并稍等，平台会调用 Zadig 服务端搜索。不要仅依赖首次加载的前若干条列表。

**Q：提交后在哪里看进度？**  
A：**项目管理 → 审批流 → 已发起**。

**Q：审批通过了，Zadig 里还没有项目？**  
A：审批通过后需申请人在详情页点击 **开始执行**，Agent 才会实际调用 Zadig API。

**Q：执行失败怎么办？**  
A：查看 Agent 日志中的错误信息；修复配置或 Zadig 侧问题后，点击 **重新执行**。若执行中断但 checkpoint 仍在，可尝试 **恢复连接**。

**Q：创建项目时 Values 文件是否必填？**  
A：否。不选择时使用 Helm Chart 模板默认值；选择后可勾选「自动同步」以代码库为准。

**Q：我没有「审批配置」「用户管理」等菜单？**  
A：这些菜单需要相应权限，请联系管理员在 **用户管理** 中分配角色。
